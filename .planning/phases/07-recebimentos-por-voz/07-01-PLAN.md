# Plan 07-01: Ditado de receita na captura por voz (VOZ-02)

## Goal
Permitir que o usuário **dite um recebimento** (ex.: "recebi 3000 de salário") e a IA **classifique o lançamento como receita**, com confirmação e edição manual do tipo antes de salvar.

## Context
- Modelo atual não distingue receita/despesa (`lancamentos` sem coluna `tipo`; `Lancamento`, `RascunhoLancamento`, prompt do Gemini e repositórios sem o conceito).
- Decisão recomendada: coluna `tipo text not null default 'despesa'` em `lancamentos` (check despesa/receita); valores em centavos permanecem positivos, sinal aplicado na UI.
- Fase 6 concluída: confirmação do ditado (`ConfirmacaoDitadoScreen`), prompt `gemini-3.5-flash-lite`, repositório `SupabaseLancamentosRepository`.
- Dois requisitos VOZ-02 ligados nesta fase; auditar exigir que a receita apareça no saldo/fluxo (07-02).

## Scope
**Inclui:**
- Migration `20260907160000_add_tipo_lancamento.sql`: `alter table public.lancamentos add column tipo text not null default 'despesa'` + check constraint + comment; aplicar no Supabase remoto via `supabase db push --linked`.
- Domínio: enum `TipoLancamento` (`despesa`/`receita`, `dbValue`, `fromDb`); `Lancamento.tipo` em `copyWith`/`toMap`/`fromMap` (fallback despesa).
- `LancamentosRepository.create/update` ganham `tipo` (default despesa); `SupabaseLancamentosRepository` grava `tipo` e copia em `gerarProximaCopiaSeFixa`; `FakeLancamentosRepository` idem.
- `RascunhoLancamento.tipo` (String? 'despesa'/'receita') + `CampoDitado.tipo` + caso no `corrigir()`.
- `GeminiPrompt`: schema JSON inclui `"tipo": "despesa"|"receita"`; regras de classificação por sinais (recebi/ganhei/salário/...); fallback `despesa`. Instrução de correção suporta `tipo`.
- `ConfirmacaoDitadoScreen`: toggle Despesa/Receita (`SegmentedButton`), inicializado de `rascunho.tipo` (fallback 'despesa'); microfone para corrigir tipo; salvar com `tipo`.
- `LancamentoFormScreen`: toggle Despesa/Receita; `_prefill` restaura `tipo` na edição; quando receita, ocultar vencimento/fixa mensal.
- Testes: modelo/migration via fake, parse do prompt com `tipo`, confirmação com toggle, form novo/edição.

**Exclui:**
- Dashboard/saldo/lista com entradas (07-02).
- Categoria própria para receitas (ex.: Salário) — adiada.
- Vencimento para receitas — fora de escopo.

## Technical Design
- Migration SQL (em `supabase/migrations/`):
  ```sql
  alter table public.lancamentos add column if not exists tipo text not null default 'despesa';
  alter table public.lancamentos drop constraint if exists lancamentos_tipo_check;
  alter table public.lancamentos add constraint lancamentos_tipo_check check (tipo in ('despesa','receita'));
  comment on column public.lancamentos.tipo is 'despesa | receita (default despesa)';
  ```
- Enum no domínio:
  ```dart
  enum TipoLancamento {
    despesa('despesa'), receita('receita');
    const TipoLancamento(this.dbValue);
    final String dbValue;
    static TipoLancamento fromDb(String v) =>
        v == 'receita' ? TipoLancamento.receita : TipoLancamento.despesa;
  }
  ```
- `Lancamento.tipo` como `TipoLancamento` com default `TipoLancamento.despesa` (não nullable — sempre presente).
- `create/update`: novo parâmetro nomeado `TipoLancamento tipo = TipoLancamento.despesa`; grava `tipo.dbValue`.
- Prompt: adicionar `"tipo": "despesa"|"receita"` ao formato; regras: receita se o usuário disser recebimento ("recebi", "ganhei", "salário", "pagamento", "transferência recebida", "depósito", "devolução de"); despesa nos demais casos ("gastei", "paguei", "comprei", "fatura", "conta"); se ambíguo, `despesa`.
- Toggle na confirmação/form: `SegmentedButton<TipoLancamento>` com ícones (trending_up/trending_down), cores (vermelho despesa, verde receita); estado `_tipo`.
- No form, `_prefill` seta `_tipo = lancamento.tipo`; campo `Vencimento`/`Fixa mensal` só exibido quando `_tipo == despesa`.

## Acceptance Criteria
1. Migration `20260907160000_add_tipo_lancamento.sql` existe em `supabase/migrations/` e aplica no remoto (`supabase db push --linked` OK); linhas antigas recebem `despesa`.
2. `Lancamento.fromMap` sem `tipo` no mapa → `TipoLancamento.despesa` (compat retroativa).
3. Prompt `payloadReconhecer` inclui `"tipo"` no JSON; `parseRascunho` extrai `tipo` e grava em `RascunhoLancamento`.
4. Ditado "recebi X de salário" → confirmação abre com toggle em **Receita**; botão de voz corrige tipo; salvar grava `tipo='receita'`.
5. Form manual novo: toggle despesa/receita, salvar com tipo; edição de receita restaura tipo (não vira despesa).
6. `flutter analyze` limpo; testes novos passam sem quebrar os existentes.
