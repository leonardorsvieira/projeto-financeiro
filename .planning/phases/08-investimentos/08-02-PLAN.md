# Plan 08-02: Compra e venda por ativo

## Goal
Registrar compras e vendas (ou aportes/resgates para RF/bco) por ativo e manter a posição atualizada (quantidade/preço/custo acumulado).

## Context
- 08-01 cria `investimentos` (posições) e a tela. Agora a posição é editada indiretamente via movimentos (D-03/D-04).
- `movimentos_investimento` = histórico; `investimentos.preco_atual_cents`/`quantidade` são derivados do último trade (mantido manualmente nesta fase simples).

## Scope
**Inclui:**
- Domain `MovimentoInvestimento` (id, investimentoId, tipo compra/venda, quantidade double, precoUnitCents, data) + `movimentos_investimento_repository` (interface `watchPorInvestimento(id)`, `create`, `delete`) + `SupabaseMovimentosInvestimentoRepository` (stream `.eq('investimento_id', id)`).
- `movimentosRepositoryProvider` + `movimentosPorInvestimentoProvider.family(id)`.
- Tela `MovimentosScreen` averiguar detalhe do ativo (rota `investimentoDetalhe(id)`): mostra posição resumida (qtd atual, preço, patrimônio), lista de movimentos, FAB "+" novo movimento; tap em um movimento → só excluir (menu) para MVP.
- `MovimentoFormScreen` (novo): Dropdown compra/venda (rotulo muda para Aporte/Resgate se RF/bco), quantidade (double), preço unitário R$ (ou valor aplicado para RF/bco), data. Ao salvar: `create` movimento e atualizar a posição no `investimentos` (quantidade +/−, `preco_atual_cents` = último preço do trade).
- Custo acumulado: provider `custoInvestidoPorAtivoProvider` soma compras − vendas (qtd×preço); usado em 08-03.
- Rotas: `investimentoDetalhe(id)`, `movimentoNovo(id)`, `movimentoEditar` (sem editar, só excluir — decision: histórico não muta).

**Exclui:** patrimônio/ganho agregado (08-03), rendimentos (08-04), voz (08-05), edição de movimentos passados.
