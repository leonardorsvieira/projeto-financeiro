## Technical Design
- `ResumoMes`:
  ```dart
  class ResumoMes {
    const ResumoMes({required this.entradasCents, required this.saidasCents, required this.previstoCents});
    final int entradasCents; final int saidasCents; final int previstoCents;
    int get realCents => saidasCents; // alias compat
    int get saldoCents => entradasCents - saidasCents;
    int get totalCents => saidasCents + previstoCents; // mantém semântica de gasto
  }
  ```
- `resumoMesProvider`: percorre lançamentos; `dataNoMes` → se `tipo == receita` soma em entradas, senão em saídas; previsto = `tipo == despesa` com vencimento no mês e `!dataNoMes`.
- Donut total: `resumo.saidasCents` (era `realCents`).
- Lista: `final ehReceita = item.tipo == TipoLancamento.receita;` cor verde (`Colors.green.shade600`) vs `colorScheme.error`; valor `'${ehReceita ? '+' : '-'} $formato...'` → melhor `'+${formatoBRL(...)}'`/`'-${formatoBRL(...)}'`; badge "Receita" com ícone `arrow_downward` (verde).
- Seção "Próximos vencimentos" já usa `proximosVencimentosProvider` (agora só despesas) — sem mudança adicional.
