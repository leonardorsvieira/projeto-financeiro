<task type="auto">
  <name>Task 2: Criar/vincular projeto Supabase remoto e obter credenciais</name>
  <files>supabase/config.toml, supabase/.temp/project-ref, .env</files>
  <read_first>supabase/config.toml, .planning/phases/01-funda-o-e-acesso/01-RESEARCH.md</read_first>
  <action>
  Com `SUPABASE_ACCESS_TOKEN` disponível na sessão:

  CASO A — projeto ainda não existe:
  1. Listar org: `supabase organizations list` → pegar o primeiro `id` (org da conta do usuário).
  2. Criar: `supabase projects create meubolso --org-id <org_id> --db-password <senha_forte_generada_localmente> --region sa-east-1` (região São Paulo; se o CLI não aceitar `sa-east-1`, usar `us-east-1` e anotar a divergência no resumo, priorizando a região livre disponível) → salvar o Project Ref retornado.
  3. Vincular: `supabase link --project-ref <ref>`.

  CASO B — usuário criou no dashboard: pedir o Project Ref (campo no dashboard Settings → General) e rodar `supabase link --project-ref <ref>`.

  Depois:
  - Obter URL + anon key: `supabase projects list` (mostra ref/org) e consultar a API de projects para `supabase_url` e `anon_key` — OU pedir ao usuário o valor de "API URL" e "anon public" (Settings → API) se a API via CLI falhar. Escrever em `.env`:
    ```
    SUPABASE_URL=<project_url>
    SUPABASE_ANON_KEY=<anon_key>
    ```
    (NUNCA o service_role key no .env do repo).
  - Habilitar e-mail: configurar via Supabase Management API (PATCH em `/v1/projects/<ref>/config/auth` com `external_email_enabled=true` e `external_email_otp_confirm_required=false`, que desabilita "Confirm email" para usuário único) — se a API não estiver acessível, instruir o ajuste manual no dashboard (Authentication → Providers → Email) no relatório do plan.
  - Rodar `supabase status` para confirmar vinculação.
  </action>
  <verify>supabase link --project-ref (exit 0) e Test-Path .env com SUPABASE_URL e SUPABASE_ANON_KEY não vazios; git check-ignore .env</verify>

    - "git check-ignore .env" não é string vazio (i.e., .env está ignorado)
    - "git status --short" NÃO lista ".env"
  </acceptance_criteria>
