# Plan 06-03: Metas/limites por categoria com progresso (DASH-04)

## Goal
Permitir que o usuário defina **meta mensal de gasto por categoria** (recorrente), editável e excluível, com **progresso** no dashboard comparado ao gasto do mês.

## Context
- Decisão: limite mensal recorrente por categoria, editável/excluível (opção recomendada confirmada).
- Supabase: tabela `metas` com RLS (mesmo padrão de `lancamentos`). 
- `lancamentosStreamProvider` já emite lançamentos; `gastosPorCategoriaMesProvider` (06-02) dá o gasto do mês por categoria.
- Fase 6 sem receitas.

## Scope
**Inclui:**
- Migration `20260907150000_create_metas.sql`: tabela `public.metas` (id, user_id, categoria, valor_limite_cents, created_at, updated_at) + RLS (select/insert/update/delete próprios) + realtime.
- Modelo `Meta` (domain) + `MetasRepository` (interface) + `SupabaseMetasRepository` (data) + `metasStreamProvider`.
- Provider `metasComProgressoProvider`: junta metas × gasto do mês por categoria (progresso %).
- Tela/seção **Metas** no dashboard (e/ou aba dedicada via `AppBar`): lista de metas com barra de progresso (ok / alerta >80% / estourada), criar/editar/excluir via dialog (categoria + valor em R$).
- Testes: provider de progresso; CRUD fake; UI minimal.

**Exclui:**
- Receitas no saldo (Fase 7).
- Metas múltiplas por categoria / por período específico.

## Technical Design
- SQL: como `lancamentos` (uuid pk, user_id default auth.uid, RLS, publication realtime), com `unique(user_id, categoria)` para uma meta por categoria.
- `Meta`: `{id, categoria, valorLimiteCents}`.
- `metasStreamProvider = StreamProvider<List<Meta>>` → repo.watch().
- `metasComProgressoProvider = Provider<List<MetaComProgresso>>` combinando `gastosPorCategoriaMesProvider` e `metasStreamProvider`; `MetaComProgresso({meta, gastoCents, pct})` com `pct = gastoCents / valorLimiteCents`.
- UI: `MetasSection` no `DashboardScreen` (abaixo do donut) + `MetasScreen` dedicada? → decisão: seção no dashboard com "Gerenciar" abrindo tela/sheet de edição.
- Diálogo de meta: select categoria (lista fixa) + campo valor (parse `parseValorBRLParaCentavos`).

## Acceptance Criteria
1. Migration aplica no Supabase remoto (via pester ou psql) — tabela + RLS + realtime.
2. Usuário cria meta (categoria + valor), vê na lista com progresso (gasto do mês / limite).
3. Progresso: verde <80%, âmbar 80-100%, vermelho >100%.
4. Editar valor/categoria e excluir meta atualizam a lista imediatamente.
5. `flutter analyze` limpo + testes passam; build web e APK OK.
