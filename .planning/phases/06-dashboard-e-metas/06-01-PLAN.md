# Plan 06-01: Dashboard base + gastos do mês (DASH-01, DASH-03)

## Goal
Transformar a primeira tela (`/home`) num painel sumário: tabs **Resumo | Lançamentos** onde o Resumo mostra o **gasto do mês** (real + previsto) e a **lista de próximos vencimentos** em destaque (DASH-03). Fase 6 sem conceito de receita (decisão: "saldo = gastos mês agora; receitas na Fase 7").

## Context
- `/home` hoje é `LancamentosListScreen` (Scaffold + AppBar 'Meu Bolso' + actions notifications/event/menu + FABs Ditar/Novo).
- `lancamentosStreamProvider` emite lista completa; `proximosVencimentosProvider` já filtra/ordena (05-01).
- `Lancamento.data` = data do lançamento; `vencimento` = data de vencimento (nullable). `valorCents` int.
- Decisões da Fase 6 (confirmadas pelo usuário): gastos do mês com previstos; donut fl_chart; tab Resumo|Lançamentos; metas recorrentes editáveis.

## Scope
**Inclui:**
- Nova tela `HomeScreen` com `TabBar` (Resumo | Lançamentos) no topo; `/home` aponta para ela.
- Refactor de `LancamentosListScreen` para ser o corpo da aba Lançamentos (AppBar actions/FABs movidos para HomeScreen).
- Dashboard (aba Resumo): card **Gastos do mês** com real + previsto; seção **Próximos vencimentos** (reuso do provider 05-01) com empty state.
- Providers derivados: gastos do mês (real = data no mês vigente) e previstos (vencimento no mês mas data fora do mês).
- Pull-to-refresh no Resumo (garante cópias vigentes).
- Testes ajustados (lancamentos_flow_test, proximos_vencimentos_screen_test) + novos de dashboard.

**Exclui:**
- Gráfico por categoria (06-02).
- Metas por categoria (06-03).
- Receitas/entradas (Fase 7).

## Technical Design
- `features/dashboard/` novo: `presentation/home_screen.dart`, `presentation/dashboard_screen.dart`; `application/dashboard_providers.dart`.
- `HomeScreen` (ConsumerStatefulWidget): `Scaffold(appBar: AppBar(title 'Meu Bolso', bottom: TabBar(Resumo/Lançamentos), actions: [notifications, event, menu]), body: TabBarView([DashboardScreen, LancamentosListScreen]), floatingActionButton: [novo, ditar])`. FABs apenas na aba Lançamentos (`IndexedStack` mantém estado, tab sync manual).
- `LancamentosListScreen`: remove AppBar/FAB → vira `ConsumerWidget` corpo puro (mantém `_Lista`, empty/error states). AppBar actions migram para `HomeScreen`.
- Providers (aplicação):
  - `gastosMesProvider` → `(realCents, previstoCents)` do mês vigente.
  - `DashboardResumo` record (real, previsto, proximosVencimentos).
- Rota: `GoRoute(path: '/home', builder: HomeScreen)`.
- `DashboardScreen`: `RefreshIndicator` + `SingleChildScrollView` com Cards (gasto real / previsto) e lista compacta de próximos vencimentos (máx ~5, link para tela completa).

## Acceptance Criteria
1. Terceira navegação `/home` abre com tabs; aba Resumo mostra card "Gastos do mês" (R$ real e R$ previsto).
2. Próximos vencimentos aparecem no Resumo (futuros, ordenados); empty state quando não houver.
3. Aba Lançamentos continua funcionando (lista + FABs + ações da AppBar).
4. Pull-to-refresh no Resumo revalida cópias vigentes.
5. Cards calculam só lançamentos do usuário (mesmo stream).
6. `flutter analyze` limpo; testes passam.
